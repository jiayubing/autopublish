# ADR 0004：按发布目标记录文章发布结果

- 状态：已废弃（2026-08-05）
- 日期：2026-07-18

> Superseded by the account-aware publication-target decision in
> `docs/refactor/04-phase-01-domain-contracts.md` and the current business
> definition in `CONTEXT.md`. This ADR is retained unchanged below as the
> historical article-by-target cutover decision; it no longer defines the
> normal-platform target key.

## 背景

一篇文章可能被投稿到多个普通平台，也可能被投稿到多个付费媒体资源。审核发生在文章本体上，而远端投稿结果发生在具体目标上。把这些结果压缩成文章的一个全局状态，会丢失目标之间的差异，也无法可靠地阻止重复投稿。

旧的 `published` 归档可以作为运行材料或兼容证据，但它既不能表达目标粒度，也不能说明一次远端调用是否已经发生。因此它不能作为历史发布结果和防重复判断的唯一依据。

## 决策

### 1. 发布记录按文章 × 目标聚合

每个文章—发布目标组合只有一份发布记录，记录状态和按时间追加的发布尝试。

- 普通平台目标键的业务粒度是 `articleKey + platformId`，例如同一文章分别投 `toutiao` 和 `hepan`，是两个独立目标。
- 付费媒体目标键的业务粒度是 `articleKey + mediaResourceId`，例如同一文章分别选择资源 `1001` 和 `1002`，是两个独立目标。
- 同一文章、同一普通平台或同一媒体资源不能因为重复点击、多个窗口或多个批次而产生第二份可执行发布记录。

发布记录是历史文章页面和重复发布保护的权威来源；队列文件、`published` 归档、订单 JSONL 和日志只保留为运行材料或兼容证据。

### 2. 不使用全局 `published`

不把文章本体简单改成全局 `published`，原因是：

1. 一篇文章发布到一个目标后，其他目标可能仍未入队、提交或发布；全局状态会错误地阻止这些合法目标。
2. 普通平台与付费媒体的重复判断键不同，单一文章状态无法表达资源级结果、订单号或目标级时间线。
3. 远端“已提交”不必然等于“已发布”，而等待核对、明确失败和已发布需要分别呈现。
4. 修改后的文章不能靠改文件名或清除全局状态绕过历史记录；重新发布修改版应创建新的文章身份。

文章继续保留自己的审核生命周期；发布结果由独立的文章—目标发布记录表达。

### 3. `uncertain` 默认阻止重试

当超时、浏览器崩溃、响应丢失或本地无法证明远端结果时，目标进入 `uncertain`。在核对之前不得直接重试，因为再次调用可能造成远端重复发布或重复扣费。

只有结果核对将目标明确转为已发布，或人工/系统确认远端未成功并将其转为可重试的明确失败，才可以继续后续处理。远端已经成功但本地归档失败时，发布记录仍须表达成功并继续阻止重复，不得把本地写入错误当作可安全重试的失败。

### 4. 发布记录属于可迁移内容库

发布记录随内容工作区备份、迁移和恢复，作为内容历史的一部分保留。它不写入安装目录、应用级秘密配置或仅存在于当前机器的临时目录；删除文章本体也不应抹掉目标级发布历史所需的最小引用。

记录只保存完成审计和重复保护所需的非敏感信息，例如文章引用、内容哈希、目标标识、状态、尝试标识、远端 ID/URL 和安全错误码；不得保存 API Key、Cookie、Authorization、客户资料全文、Prompt、浏览器 profile 或远端完整响应。

迁移必须保留既有记录，不以迁移为由删除旧队列、订单、归档或用户内容。无法证明旧材料对应某个文章—目标或无法证明远端成功时，不制造 `published` 事实。

## 后果

- 历史页面可以同时显示审核状态与每个普通平台/媒体资源的发布摘要。
- 一个目标已发布不会阻止同一文章投向其他目标；同一目标的 `queued`、`submitting`、`submitted`、`published` 和 `uncertain` 都会阻止重复占位。
- 明确失败可以追加新的发布尝试，但发布记录身份保持不变。
- 队列、归档和订单仍可用于运行与兼容，但不能绕过发布记录进行强制重复发布。
