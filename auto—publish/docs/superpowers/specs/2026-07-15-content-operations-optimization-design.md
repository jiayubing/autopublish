# AI 内容采集、批量生成与审核优化设计

## 目标

优化 AutoPublish 的“AI 内容生成”工作台，使大量客户的定期豆包采集、客户资料管理、跨平台批量文章生成、历史审核和 AI 接口配置形成稳定闭环，同时保持客户数据、写作模板、文章和投稿流程的现有安全边界。

## 范围

本次包含：

- 采集页批次客户全选与明确的普通采集/重新采集命令。
- 最后一个采集任务结束后自动关闭豆包浏览器。
- 采集任务脱离当前 React 页面生命周期。
- 采集回答与生成回答默认折叠。
- 删除采集页重复的当前客户选择器。
- 客户资料在生成页展示、选择和预览。
- 客户文件夹第一层 DOCX 转换、缓存和错误恢复。
- 单篇生成与跨客户、跨平台模板批量生成。
- 持久生成批次、失败重试、停止和恢复。
- 批量生成文章自动保存、单篇和批量审核。
- 当前客户历史文章按平台与模板分组。
- 配置中心管理应用级 OpenAI 兼容接口。

本次不包含：

- 隐藏或 headless 豆包浏览器采集。
- 客户资料子目录递归读取。
- AI 请求并发执行；仅预留并发契约。
- 自动截断、自动摘要或向量检索。
- 批量生成后自动投稿。
- 迁移或改造文章在磁盘上的客户归属目录。

## 领域关系

客户资料是文章事实与品牌信息的基准，GEO 调研回答用于指导豆包推荐语境、选题和信息组织。单篇或批量生成都必须同时选择至少一份有效客户资料和至少一条有效 GEO 调研回答。

批量生成采用：

```text
生成任务 = 客户 × 写作模板
任务总数 = 批次客户数 × 跨平台模板数
```

同一客户在一个生成批次中只维护一套生成来源集，该客户的所有模板任务共用。模板负责写作场景和平台要求，不改变客户事实来源。

## 采集页面

### 客户选择

页面顶部唯一的“当前客户”控制正在查看和编辑的客户。删除 `QuestionCollectionView` 内部重复的当前客户下拉框。

“批次客户”是独立多选集合，不随当前客户切换而自动改变。批量区域提供：

- 全选客户。
- 取消全选。
- 已选客户数量。
- 预计进入队列的已启用问题数量。

全选永远只包含各客户的已启用问题；停用问题明确排除。

### 采集命令

提供两个独立按钮：

- `采集选中客户`：只将缺少成功回答的已启用问题加入批次；已有成功回答跳过。
- `重新采集选中客户`：将所有已启用问题以覆盖模式加入批次，启动前显示客户数、问题数并二次确认。

全选只改变选择范围，不自动启动任务。重新采集只有在新回答成功保存后才覆盖旧回答；失败保留旧成功结果。

### 回答折叠

每个问题的回答和引用默认折叠。用户可以同时展开多条；展开只影响阅读，勾选、启用、采集和编辑状态不受影响。回答摘要行显示状态、字数、采集方式和采集时间。

### 客户选择去重

顶层当前客户选择器在三个内容标签页保持一致。采集页不再重复显示单客户选择器；批次多选必须明确标注“批次客户”，避免与当前客户混淆。

## 采集会话生命周期

豆包采集队列位于 Electron 主进程服务，不能依赖 `QuestionCollectionView` 是否挂载。用户切换到文章生成、历史文章或其他工作台后，采集继续运行并通过全局事件更新状态。

浏览器关闭规则：

- 单条任务成功或失败且没有后续任务时关闭。
- 批次最后一项完成后关闭。
- 队列停止或全部取消后关闭。
- 批次暂停且仍有后续任务时保持打开。
- 仅打开登录页且尚未启动采集时保持可见。
- 应用退出时关闭。

关闭浏览器不删除 Playwright profile，登录状态可在下一次采集复用。adapter 增加 `visible | background` 运行模式边界，本次只实现并验收 `visible`；后续隐藏/headless 模式不得改动队列、存储或 IPC 契约。

## 客户资料

### 文件范围

只读取客户文件夹第一层的：

```text
.txt
.md
.markdown
.json
.docx
```

所有子目录及其中任意格式文件均忽略。`questions.json`、`client.json`、`search_query.txt` 和生成文章目录不属于客户资料。

### DOCX 转换

DOCX 使用现有 MarkItDown 运行依赖转换为文本，原文件永不修改。缓存键至少包含文件内容 SHA-256 和转换器 schema 版本，缓存位于工作区私有缓存目录，不写入客户文件夹，也不进入安装包。

DOCX 未变化时复用缓存；文件变化后重新转换。转换失败时：

- 文件仍显示在客户资料列表。
- 标记损坏、加密文档、MarkItDown 不可用或转换失败等安全错误。
- 自动取消该文件的生成勾选。
- 不阻断其他资料和回答读取。
- 提供“重新转换”。

如果客户因此没有至少一份有效资料，则该客户不可生成。

### 生成页资料选择

客户资料按文件展示，默认全部折叠、全部勾选。展开控制文本预览，checkbox 控制是否进入 AI 输入，两种状态完全独立。显示文件名、格式、转换状态、提取字数和折叠内容。

单篇和批量预览显示预计输入字符数，但不设置本地硬上限，不自动截断或摘要。供应商返回上下文过长时，任务失败并提示用户减少资料或回答后重试。

## 文章生成页面

文章生成页顶部使用 `单篇生成 / 批量生成` 分段控制。

### 单篇模式

保留当前客户、回答选择、平台、模板、文章编辑、保存和导出流程。回答列表默认全部折叠，可同时展开；勾选不自动展开。客户资料与回答都必须至少选一项。

### 批量模式

采用页面内四步流程：

1. 选择批次客户，支持全选和取消全选。
2. 选择跨平台写作模板，按平台分组。
3. 检查每个客户的生成来源集。
4. 确认任务数并启动，随后显示批次进度。

第三步为每个客户显示：

- 有效客户资料和勾选状态。
- 有效 GEO 调研回答和勾选状态。
- 预计输入字符数。
- 可生成或不可生成原因。

每个客户只配置一次来源集，该客户所有模板任务共用。不可生成客户从可执行任务中排除并明确显示，不阻断其他客户；启动确认必须列出排除客户数量和原因。

启动前显示：

```text
客户数 × 模板数 = AI 调用任务数
可执行任务数
被排除客户与任务数
```

## 生成批次

### 持久化

每次确认启动创建新的批次 ID。即使客户和模板选择相同，新批次仍可生成新文章。同一批次内任务具有稳定 ID，身份包含客户 ID、平台和模板 ID。

批次保存：

- 批次 ID、创建时间和状态。
- 客户选择、模板选择和来源文件/回答 ID。
- AI 配置指纹，不保存 API Key。
- 每个任务状态、尝试次数、错误和生成文章 ID。
- 总数、成功数、失败数、pending 和 interrupted 数。

应用重启后不自动恢复请求。界面提示未完成批次，用户明确点击继续后只执行 pending、failed 和 interrupted，跳过 succeeded。

### 执行和并发预留

第一版 `concurrency = 1` 串行执行。执行器、任务锁、状态写入和幂等保存不得依赖任务顺序；接口保留受验证的 concurrency 参数，UI 不开放修改，为后续并发升级预留。

每篇成功后立即保存文章并原子更新任务状态。文章保存成功但批次状态更新失败时，恢复逻辑通过 article ID/批次 task ID 识别已完成任务，不能再次调用 AI。

### 失败策略

- `429`、网络错误、timeout、`5xx`：自动重试两次，等待 5 秒和 15 秒。
- `401/403`、模型不存在、AI 配置无效：暂停整个批次。
- 空输出、文章解析失败、上下文过长：当前任务失败，继续下一任务。
- “重试失败”只执行 failed，不重复 succeeded。

停止时向当前 AI 请求发送取消信号；当前任务标记 interrupted，未开始任务保持 pending，批次变为 stopped。用户以后明确继续。供应商已开始处理时仍可能计费，界面应提示。

### 来源读取

不保存批次级完整来源快照。每个任务开始时读取当前选择的资料与回答；中途资料变化可影响后续任务。每篇文章保存自己实际使用的文章来源快照和模板版本快照，保证单篇可追溯。

## 文章保存与审核

单篇生成继续由用户编辑后保存。批量任务成功后立即保存为 `generated`，属于待审核文章，不能导出到待投稿队列。

人工保存或批量审核后状态变为 `saved`，记录 `reviewedAt`。批量审核：

- 只处理用户明确勾选的 `generated` 文章。
- 支持全选当前模板组和全选当前筛选结果。
- 生成批次详情支持跨客户选择和审核。
- 当前客户历史页支持模板组内审核。
- 标题/正文为空、来源缺失或文件损坏的文章拒绝通过，并列出原因。
- 已 saved 文章幂等跳过，不重复更新时间。
- 审核不会自动导出或投稿。

只有 saved 文章可以进入现有待投稿队列。

## 历史文章

历史页继续受顶部当前客户控制。结构为：

```text
当前客户
  平台 + 模板版本快照 A
    文章（按 createdAt 倒序）
  平台 + 模板版本快照 B
    文章（按 createdAt 倒序）
```

模板组默认折叠，显示文章数、待审核数和最新生成时间。模板组按组内最新 createdAt 倒序，组内文章按 createdAt 倒序。updatedAt 和 reviewedAt 只展示，不影响默认顺序。

分组键为 `platform + templateId`。模板改名、修改或删除后，历史文章使用生成时模板版本快照的名称、场景和正文解释与显示。磁盘继续按客户存储，不迁移文章目录。

## 模板与文章来源快照

新文章保存：

- 实际使用的客户资料文件名、文本、内容哈希和转换来源。
- 实际使用的 GEO 调研问题、回答、引用和采集时间。
- 模板平台、ID、名称、场景、完整正文和正文哈希。
- 生成批次 ID 和任务 ID（单篇为空）。

快照不包含 API Key、媒体凭据、浏览器 profile、完整工作区路径或未勾选资料。

## AI 配置中心

### 归属与优先级

AI 提供方配置属于应用级配置，所有工作区共用。工作区 `.env` 中的 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 和 `AI_TIMEOUT_MS` 不再读取；媒体投稿等非 AI 配置继续按原规则使用工作区 `.env`。

优先级：

1. 操作系统或启动命令显式设置的 AI 环境变量。
2. 配置中心保存的应用级配置。

环境变量覆盖时 UI 显示来源并只读。

### 配置字段

- OpenAI 兼容 Base URL，只允许 HTTPS 或 localhost HTTP，填写到 `/v1`，拒绝完整 `/chat/completions`。
- API Key。
- 模型名称。
- 超时时间。

API Key 使用 Electron safeStorage 加密后保存在 Electron userData；Renderer 只能获得 `hasApiKey` 和掩码，不得读取保存明文。Base URL、模型和 timeout 与密文保存在应用配置，不进入 workspace、日志或安装包。

### 操作

- 保存：本地校验后立即供下一次生成使用，不发网络请求。
- 测试连接：使用当前表单执行最小 completion，明确提示可能产生少量费用；失败不覆盖已生效配置。
- 清除：二次确认后删除加密应用配置和测试状态；环境变量存在时仍由环境变量接管。
- 显示最近测试时间、结果和配置来源，不保存测试回答正文。

生成批次 running/stopping 时禁止保存、测试或清除。批次 stopped 后修改配置，再继续未完成批次时提示配置指纹已经变化。

## 错误与状态

新增稳定错误类别：

- 客户没有有效客户资料。
- 客户没有有效 GEO 调研回答。
- DOCX 转换失败或 MarkItDown 不可用。
- 生成批次正在运行、停止或配置变化。
- AI 配置未设置、加密不可用、连接失败或上下文过长。
- 批量审核文章无效。

IPC 错误只返回安全 code/message，不包含 API Key、客户资料全文、Prompt、绝对缓存路径或 provider 响应 body。

## 验收标准

- 采集页只有一个当前客户选择器，批次客户支持全选且只处理 enabled。
- 普通批量采集不覆盖成功回答，重新采集明确确认后才覆盖。
- 最后一个采集任务后浏览器自动关闭，切换页面不停止采集。
- 回答和客户资料默认折叠，展开与勾选互不影响。
- 所有客户资料格式只读第一层；DOCX 可缓存转换并单独重试。
- 单篇和批量任务同时要求客户资料与 GEO 调研回答。
- 客户 × 跨平台模板任务数量、进度和调用次数准确。
- 生成批次可停止、持久化、恢复和重试，不重复成功任务。
- 批量文章自动保存为待审核，明确批量审核后才能导出。
- 当前客户历史文章按平台与模板分组，按生成时间倒序。
- 模板变化不改写历史分类和解释。
- AI 配置应用级共享、加密保存，不读取工作区 AI `.env`。
- 本次不声称隐藏/headless 采集可用，但 adapter 已预留模式边界。
- 现有媒体投稿、平台投稿、工作区选择、旧 research 和旧文章保持兼容。
- 自动测试、构建、验证和 alpha 打包全部通过。
