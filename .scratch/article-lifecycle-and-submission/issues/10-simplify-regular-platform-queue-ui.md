# 10 — 精简普通平台投稿队列界面

**What to build:** 以队列组为中心展示普通平台任务，只显示组状态、当前文章和剩余顺序，并提供清晰的追加、移除、开始与暂停操作。

**Blocked by:** 09 — 普通平台结果分类与人工收口

**Status:** COMPLETE；Dependency-Resolution Lane implementation `9124f0148eb4b91ba83ead95203135f12b60b99a`，audit / bounded re-audit PASS

**Scheduling gate:** Ticket 09 已完成；Wave 6 `COMPLETE` gate 仅由已授权 Dependency-Resolution Lane 豁免。完成 evidence 见 `handoffs/10-simplify-regular-platform-queue-ui.md`。

## 启动约定

- 确认 08、09 已提供稳定队列组快照、控制命令和人工核对动作。
- 阅读规格中“队列内部不要逐篇重复状态”的决定，先记录当前多目标选择器、逐项状态和页面组件职责。

## 执行过程

1. 建立 Renderer 队列组只读模型和 feature 控制器，所有数据来自 typed bridge，不在组件中计算业务状态。
2. 入队界面一次只允许选择一个普通平台；存在一个账号时隐藏账号层，多个账号时要求明确选择。
3. 每个组展示总体状态、账号（必要时）、当前文章、剩余文章顺序和明确异常提示，不为每篇等待项重复组状态。
4. 接入追加文章、单篇/批量移除 pending 项、开始组、暂停组、开始全部和暂停全部。
5. 对 uncertain 项只显示 09 提供的两种核对动作；不出现直接重试。
6. 拆分现有超长文章管理/平台组件，让页面组件只负责布局，feature 负责命令状态与请求身份。
7. 增加桌面和窄宽度交互、键盘焦点、并发命令禁用、客户切换和失效刷新测试。

## 职责边界

- Renderer feature 拥有请求身份、加载/错误状态和命令协调，不拥有业务状态机。
- 展示组件只渲染传入模型并发出用户意图。
- 主进程投影拥有可执行动作和原因；界面不得从原始状态字符串猜测。
- 普通平台页面不得出现网站媒体付费确认或订单控制。

## 架构硬门槛

- 组件按可独立理解的交互职责划分；只有组列表、控制栏、核对面板形成真实维护与测试边界时才拆分，禁止为缩短文件制造透传组件或平行状态。
- feature 对外提供少量命令和只读状态，不把 bridge 对象直接传遍组件树。
- 不复制平台账号、可移除、可开始或 uncertain 判断。
- 保持可替换投影和可测试 UI，不依赖真实浏览器平台。

## Acceptance criteria

- [x] 队列按平台和账号分组，页面不再为每篇等待文章重复显示具体状态。
- [x] 单账号隐藏账号层，多账号必须明确选择且不会串号。
- [x] 追加、移除、开始、暂停、开始全部和暂停全部行为与主进程投影一致。
- [x] 手工暂停不会被开始全部覆盖，uncertain 不显示重试。
- [x] 普通队列页面不触发任何付费媒体动作。
- [x] 交接记录包含组件职责图、feature 接口、窄屏证据、依赖方向及显著规模变化说明。
