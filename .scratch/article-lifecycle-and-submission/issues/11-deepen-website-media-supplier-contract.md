# 11 — 网站媒体服务商契约深模块

**What to build:** 建立网站媒体专用供应商适配边界，稳定封装媒体资源、文章投稿、订单详情和取消订单契约，并把服务商字段与错误转换为安全规范结果。

**Blocked by:** None — can start immediately

**Status:** complete；已进入集成历史，不因后续 ticket 重新调度

## 启动约定

- 当前范围只包括服务商“网站媒体”，明确排除第三方自媒体。
- 以已确认 API 文档和现有内存传输测试为依据；不得发送真实付费请求或依赖真实凭据。
- 记录现有适配器仅支持资源、投稿、订单查询的缺口，以及 `third_id/submitted` 等旧命名。

## 执行过程

1. 定义供应商端口：刷新媒体资源、创建订单、查询一个或多个订单、取消订单；预留但不实现自动申诉。
2. 为资源可用性、价格、备注、订单号、状态码 0/1/2/4/9、取消结果和传输失败建立封闭规范 DTO。
3. 将 API key、媒体资源 ID、标题、HTML 正文、可选备注和系统投稿标识码映射到供应商请求；系统标识码不得充当幂等键。
4. 严格解析响应：只有明确成功且包含订单号才返回 order_created，缺订单号属于 uncertain，不创建伪订单。
5. 将 HTTP、字段别名和供应商错误集中在适配器；应用层只看规范结果与错误范围。
6. 使用内存传输覆盖正确请求、异常响应、超时、取消成功/拒绝、批量订单详情和未知状态。

## 职责边界

- 供应商客户端只负责 HTTP/multipart 和原始响应边界。
- 供应商适配器只做契约映射，不决定批次暂停、文章冻结或界面分类。
- 应用服务决定费用确认、串行执行和人工核对。
- Renderer 永远不接触 API key、原始状态字段或供应商错误正文。

## 架构硬门槛

- 客户端、响应解析、规范映射分别独立，目标各不超过 250 行、硬上限 400 行。
- 不用一个 catch-all adapter 承载资源缓存、订单业务状态和 UI 投影。
- 端口可用假传输完整测试，不能要求 Electron 或真实网络。
- 禁止新增服务商字段到通用文章模型。

## Acceptance criteria

- [ ] 网站媒体资源、创建订单、订单详情和取消订单均通过独立供应商端口访问。
- [ ] 只有明确成功且返回订单号才产生 order_created 结果。
- [ ] 状态 0、1、2、4、9 和未知状态映射稳定且原始字段不泄漏应用层。
- [ ] 超时、断线、缺订单号与解析异常保留为可区分的 uncertain/transport 结果。
- [ ] 第三方自媒体接口没有被读取、注册或暴露。
- [ ] 交接记录包含规范契约、字段映射、错误矩阵、测试传输和模块行数。

## Non-goals

- 不决定文章分类、付费批次暂停或人工核对。
- 不实现图片上传、真实下单或自动申诉。
