## 待确认与下一步

- 订单/对账等其他无页读取的 20000 上限：逐个确认当前消费者是否仍依赖完整全集，以合成超限末页和执行身份反例证明后再修；不能把更大 LIMIT 当修复。
- 代表性文件规模：现有 SQL/合成摘要结果不证明大量真实文件冷盘 I/O、非空恢复、Electron 帧率或真实文章长度分布。只对用户实际容量目标测量，不读生产内容做默认基准。
- 历史可靠性 R4/R5 文档仍留 PR/主线门禁待办，后续代码已有变更；最终候选验证按现行 CI 对账，不能把旧 PR 未合并标签当当前事实，也不能仅凭本地通过声称远端已通过。下一候选发布时核对 source/产物，关闭证据缺口。
- 条件 Q1：单个坏档案若确实阻断其他内容浏览，先复现再设计显式不可用项；缺少生命周期事实仍禁止重投，不吞错伪造未发布。
- 条件 Q2：采集当前运行队列在内存，已保存回答可补采缺失，但不等于恢复原批次选择。只有真实长批次需要且测量支持时增加最小恢复信息，不照搬付费事务。
- 条件 Q3/Q4：只在触及消费者时收窄内部 port/重复 guard；只有小优化后仍有明显主线程/载荷/写入瓶颈才做分页或存储拆分。保留 IPC、磁盘和副作用边界校验，不全仓机械删 guard。

每次选一个可复现问题，先记录输入规模/读取量/返回体/耗时，再最小修改与行为回归；无收益即记录不采用。整体完成不能只靠单一 SQL 数量或本机耗时。复杂度旧规划的文件数量和命名不构成新任务。
