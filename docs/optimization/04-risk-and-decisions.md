# 实施风险与待决策事项

> 本文记录无法仅凭当前仓库代码可靠决定的事项。缺少决定时，不得用默认假设扩大实施范围。

## 本地 Git 验收决定（2026-07-24）

本项目只使用本地Git里程碑提交，不配置remote、不创建PR、不push，也不使用remote required checks。根`.github/workflows/ci.yml`保留为可移植自动化配置和静态验证对象；真实PR/push触发为`NOT_APPLICABLE`，不得作为Phase 0阻塞或完成条件。Phase 0仍必须实际运行适用canonical本地门禁，尤其`npm run test:links`；本机缺少真实file symlink能力时阶段必须保持`BLOCKED`。正式签名、发布和生产运维所有权仍由其后续阶段保留。

## 3. 决策 D-001：媒体生产传输方案

- 状态：已决策（2026-07-25，用户确认服务商当前只提供HTTP，本轮允许媒体provider受控HTTP例外）。
- 决策问题：媒体API应使用哪个可信HTTPS endpoint；是否存在必须保留HTTP的受控网络例外？
- 背景：客户端默认公网 `http://8.138.187.158:8082`，API key和完整稿件以multipart发送；默认地址还绕过显式确认。
- 可选方案：
  1. 部署正式HTTPS域名/证书并将客户端改为fail-closed（推荐）。
  2. 在受控专网/VPN内短期保留HTTP，使用有到期日的显式feature flag和现场网络证明。
  3. 服务商仅提供公网HTTP期间，删除隐式默认但允许操作者显式配置和确认风险。
- 各方案影响：方案1安全、长期维护清晰，但当前服务商不支持；方案2依赖尚未具备的网络边界；方案3保留媒体能力但仍暴露凭据/正文，需要持续风险提示并在HTTPS可用后迁移。
- 决定：当前采用受控HTTP例外，但不沿用隐式默认。endpoint必须显式配置，HTTP必须显式`allowInsecure`确认并持续显示不加密风险，settings与底层client双边校验；不得从HTTPS静默降级或扩展到其他provider。服务商提供HTTPS后优先切换到方案1。
- 不做决定的后果：已不适用；决定已作出。若撤销风险接受，必须禁用媒体功能直到HTTPS可用。
- 被阻塞的优化项：无；OPT-008可实施。真实付费投稿仍须授权人工验收。

## 4. 决策 D-002：普通平台账号模型

- 决策问题：产品是否只支持“每平台永久一个账号”，还是需要正式多账号/多品牌发布？
- 背景：browser profile和publication target当前只有平台ID，执行时无法证明账号未变化。
- 可选方案：
  1. 单账号产品约束：保存expected account fingerprint，换号即阻断旧队列（推荐的最小方案）。
  2. 正式多账号：账号ID进入profile、queue sidecar、targetKey和ledger，进行兼容迁移。
  3. 不记录账号，继续依赖操作员约定。
- 各方案影响：方案1复杂度中、兼容风险低但不支持并行账号；方案2能力完整但改变去重域、迁移与UI复杂；方案3可能投错账号且不可审计。
- 推荐方案：若没有明确多账号需求，先选方案1；未来真实需求出现再单独设计方案2。
- 不做决定的后果：F-M17保持待确认，不能安全修改target schema，也不能宣称换号安全。
- 被阻塞的优化项：OPT-029；OPT-006的文章级证据可独立进行。

## 5. 决策 D-003：浏览器平台成功证据与现场验证权限

- 决策问题：能否提供脱敏DOM/响应fixture和非生产测试账号，并允许受控提交/撤回测试？
- 背景：代码已证明头条/列举弱谓词，但真实DOM频率和可获取的文章级标识未知。
- 可选方案：
  1. 提供fixture+测试账号，在shadow模式比较新旧判定（推荐）。
  2. 仅提供fixture，不做真实提交；上线时所有弱证据退uncertain。
  3. 无任何外部证据，保留旧published谓词。
- 各方案影响：方案1验证最充分但需要账号/发布治理；方案2更保守、人工核对增加；方案3继续错误成功风险。
- 推荐方案：方案1；若无法授权则方案2，不选方案3。
- 不做决定的后果：OPT-006只能完成本地负向测试，不能启用新的production成功判定。
- 被阻塞的优化项：OPT-006的production启用；不阻塞OPT-005。

## 6. 决策 D-004：Auth灾备目标、RPO/RTO与演练范围

- 决策问题：备份保存在哪里、保留多久、是否加密/异地，目标RPO/RTO是多少，谁批准隔离恢复？
- 背景：代码可修复目标校验和零副作用，但仓库无法证明备份频率和真实恢复能力。
- 可选方案：
  1. 定时online backup + 加密异地保留 + 定期隔离恢复（推荐）。
  2. 本机轮换备份 + 人工抽检。
  3. 只依赖数据库卷，无独立备份。
- 各方案影响：方案1恢复证据最好且运维成本最高；方案2仍有主机级单点；方案3无法满足可靠回滚。
- 推荐方案：按业务容忍度定义RPO/RTO后选方案1；小规模也至少定期隔离restore-check。
- 不做决定的后果：OPT-010代码可完成，但不能验收“生产可恢复”或宣称RPO/RTO。
- 被阻塞的优化项：OPT-010的生产级完成门禁。

## 7. 决策 D-005：本地Git验收与后续生产发布所有权

- 决策：Phase 0 只以 canonical 本地门禁、根workflow静态契约和本地Git里程碑commit验收。remote、PR、push与托管 required checks 统一为`NOT_APPLICABLE`；不得把它们作为 OPT-001 或 Phase 0 的完成条件。
- 背景：本项目已明确不配置remote、不创建PR、不push。根`.github/workflows/ci.yml`仍是可移植自动化配置，必须继续接受静态契约测试，但不代表托管触发已执行。
- Phase 0影响：OPT-001在全部适用本地门禁通过并形成里程碑commit后即可完成；不需要真实PR或托管required check证明。
- 后续保留：正式签名、发布、证书和生产运维审批仍属于后续正式发布阶段的人工所有权，不能由本地Phase 0替代或宣称已验收。
- 被阻塞的优化项：无本地Phase 0阻塞；OPT-007的正式签名/release验收仍等待生产所有权与人工授权。

## 8. 决策 D-006：失败诊断图像是否必要

- 决策问题：结构化摘要是否足够，还是运营必须保留页面图像？
- 背景：当前PNG是原始整页像素，正常失败会落盘敏感内容。
- 可选方案：
  1. 默认仅结构化摘要（推荐）。
  2. 仅保存固定安全区域并遮罩文本/头像/账号，短期保留。
  3. 保留原始整页截图。
- 各方案影响：方案1泄漏面最小但诊断视觉信息少；方案2需要持续DOM/像素测试；方案3不可接受。
- 推荐方案：方案1；只有明确诊断案例证明需要时才增加方案2。
- 不做决定的后果：实施线程应默认无图以fail closed，不得继续原始截图。
- 被阻塞的优化项：不阻塞OPT-011安全止损；只阻塞“安全裁剪图像”可选分支。

## 9. 决策 D-007：实时 publish-log 的用户价值

- 决策问题：UI是否需要实时投稿日志，还是结构化任务快照+attention+文件日志足够？
- 背景：sender存在而无consumer，但没有产品契约要求日志UI。
- 可选方案：
  1. 删除死sender，可靠性依赖结构化状态（推荐）。
  2. 增加typed、脱敏、有背压的日志面板。
  3. 直接把现有原始entry暴露给renderer。
- 各方案影响：方案1最小interface；方案2有运维价值但扩大信息面；方案3可能泄漏路径/内容且不可接受。
- 推荐方案：当前选方案1；有实际用户需求和脱敏规范后再选方案2。
- 不做决定的后果：OPT-028保持暂缓，不影响核心恢复。
- 被阻塞的优化项：OPT-028。

## 11. 破坏性兼容与迁移风险

- OPT-008会阻断缺少显式风险确认的旧HTTP配置；迁移需补确认或关闭媒体，不恢复隐式默认。
- OPT-013为batch增加revision；新writer启用后旧版本不得继续写同workspace。
- OPT-029若选多账号会改变publication targetKey，是最高兼容风险，必须双读、dry-run、映射与回滚。
- OPT-003可能把旧stranded `submitting`转成需核对；不能自动改failed/published，历史状态变更必须留审计。
- OPT-010验证器必须只读；任何“恢复”实际覆盖生产库都不属于Codex可自动执行范围。

## 12. 不适合由 Codex 自动实施或自动验收

- 使用真实头条、列举、河畔、媒体生产账号投稿、扣费、撤回或换号。
- 配置生产DNS、证书、Cloudflare Tunnel、WAF、VPN、防火墙和可信代理头。
- 使用或导出真实API key、Cookie、客户稿件、浏览器profile、诊断PNG或生产备份。
- 覆盖/恢复生产auth数据库、执行破坏性migration、删除备份或定义RPO/RTO。
- 采购/使用代码签名证书、发布正式安装包、处理SmartScreen审批。
- 决定单账号/多账号、订单删除保留、日志产品面等业务语义。
- 将弱平台信号人工标记为published；必须由授权操作员核对远端事实。
